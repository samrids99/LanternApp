# ADR 004: Strip photo EXIF data server-side

- **Status:** Accepted
- **Date:** 2026-11-03

## Context

Photos taken on phones usually contain EXIF metadata, including GPS coordinates. Lantern's principle is that exact locations are never shared (ADR 001). Uploading photos with their EXIF data intact would defeat that, and is likely the largest accidental leak risk in the app.

## Decision

All uploaded images will have **all EXIF and other metadata removed on the server** during upload processing (e.g. with SixLabors.ImageSharp), before being stored. The client may also strip metadata, but is never relied on.

Uploads are also validated server-side for file type and size, resized and compressed, and stored in object storage rather than the database.

## Consequences

- Guarantees no embedded location data is ever served, regardless of client behaviour.
- Adds image processing cost on upload.
- Orientation must be applied before metadata is removed, otherwise photos can appear rotated.
- Behaviour must be covered by automated tests (upload a photo with GPS metadata and assert it is absent from the stored file).
