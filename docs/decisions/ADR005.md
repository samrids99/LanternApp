# ADR 005: Cursor-based pagination for the feed

- **Status:** Accepted
- **Date:** 2026-11-03

## Context

The feed shows stays newest first, and new posts arrive while people scroll. Offset-based pagination (page number and size) can show duplicates or skip items when the underlying data changes between requests, and gets slower on large offsets.

## Decision

The feed API will use **cursor-based (keyset) pagination**. Each response returns a cursor derived from the last item's sort key (creation time plus ID as a tiebreaker), and the next request asks for items after that cursor.

## Consequences

- Stable results while new posts are added.
- Efficient queries using an index on the sort key.
- No random access to "page 7", which is acceptable for an infinite-scroll feed.
- Slightly more complex to implement and test than offset paging.
- The mobile client uses TanStack Query's infinite query support with the returned cursor.
