# ADR 003: React Native (Expo) with ASP.NET Core, EF Core and PostgreSQL

- **Status:** Accepted
- **Date:** 2026-11-03

## Context

Lantern is mobile-first, since users are on the road, often with patchy signal. The project is a solo build and is also intended to demonstrate skills from a Level 4 Software Developer apprenticeship. C# and .NET are the preferred backend skills, and a cross-platform mobile client avoids building two native apps.

## Decision

- **Mobile:** React Native with Expo and TypeScript. TanStack Query for server state, Zod for form validation.
- **API:** ASP.NET Core Web API (C#) with EF Core, using a layered architecture (Api, Application, Domain, Infrastructure).
- **Database:** PostgreSQL via Npgsql.
- **Auth:** ASP.NET Core Identity with JWT access and refresh tokens, not custom-built authentication.
- **API contract:** OpenAPI/Swagger, with a generated TypeScript client so mobile and API cannot drift apart.
- **Testing:** xUnit, NSubstitute and Testcontainers for the API; Jest and React Native Testing Library for mobile.
- **CI:** GitHub Actions for both projects.

## Consequences

- Expo simplifies builds, image picking and distribution (EAS) for a solo developer, at the cost of some native-module flexibility.
- Two languages (C# and TypeScript) means two toolchains and two CI pipelines, kept in one monorepo.
- A generated client adds a build step but removes a class of integration bugs.
- PostgreSQL is free and widely hosted. PostGIS is not needed for the MVP (see ADR 001).
