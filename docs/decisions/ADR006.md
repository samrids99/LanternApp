# ADR 006: Region granularity and picker

- **Status:** Proposed
- **Date:** 2026-11-04

## Context

ADR 001 decided that Lantern stores only a user-selected region, never coordinates. That raises follow-up questions: how detailed should regions be, which levels can a stay attach to, and how does a user choose one without being encouraged to reveal the exact spot?

A map with a draggable pin would suggest precision the app deliberately avoids and invite users to mark the exact location. It is also harder to make accessible and slower on poor signal.

## Decision

**Picker**

- Use a **searchable, hierarchical list**, not a map picker.
- Search and browse sit on one screen. Typing shows matches with a breadcrumb (e.g. "Applecross, Highlands · Scotland"). Browsing drills down country, then area, then locality.
- Recently used regions appear at the top.
- The selected region shows as a chip on the create-stay form, with a Change button.
- Reassuring copy appears at the point of choice: "We only share the area, never the exact spot."
- Users can choose a larger parent area if unsure.

**Granularity**

- Hierarchy is capped at **three levels**: country, area, locality.
- A stay can attach to **any level**. Stay counts on the map roll up the tree, so a parent region includes its children.
- Regions are seeded for the **UK first**. Other countries are added later.
- If a place is missing, users are told to choose the nearest larger area. Suggesting new regions is Phase 2.

**Data and performance**

- The region list is served from one API endpoint with an ETag, cached on the device and searched client-side, so it works with patchy signal.
- The picker is a single reusable component, also used for feed filtering and the map.

## Consequences

- The interface itself encourages area-level sharing, and reinforces the privacy principle.
- The map needs rollup logic (a recursive or precomputed count per region).
- Region data must be sourced from open data (OpenStreetMap, Natural Earth, ONS) and licences checked. Seeding and tidying the data is real work.
- Deeper hierarchies are not supported. Revisit if three levels prove too coarse.
- Optional "suggest from my location" (resolving on the device so coordinates are never sent) is deferred to the backlog.
- The picker must meet accessibility basics: large tap targets, labelled controls and clear focus order.

## Open questions

- Exact seed set for the UK and the level naming (e.g. National Park, island, coastal stretch).
- Whether any regions should be too small to offer, to protect sensitive spots.

Mark this ADR **Accepted** once the open questions are settled.x
