# ADR 007: Use .NET 10 (LTS) for the API

- **Status:** Accepted
- **Date:** 2026-11-04

## Context

The Lantern API is built with ASP.NET Core and EF Core (ADR 003). The development machine initially had only the .NET 8 SDK installed.

.NET 8 is a long-term support (LTS) release, but its support is scheduled to end in November 2026, which is the month this project starts. .NET 10 is the current LTS release. Building a new project on a framework that is about to go out of support would mean security patches stop early in its life, and a forced upgrade soon after.

All planned dependencies (ASP.NET Core Identity, JWT bearer authentication, EF Core, Npgsql, xUnit, Testcontainers) support .NET 10.

Support dates should be confirmed on the official .NET support policy page: https://dotnet.microsoft.com/platform/support/policy/dotnet-core

## Decision

Target **.NET 10** for all API projects (`net10.0`).

- Install the .NET 10 SDK locally.
- Pin the SDK with a `global.json` in `api/`, so local development and CI use the same version.
- Use `10.0.x` in the GitHub Actions `setup-dotnet` step.
- Keep NuGet package versions aligned with the framework (EF Core and Npgsql 10.x) to avoid restore and runtime mismatches.

## Consequences

- The project stays on a supported LTS release for the full life of the portfolio piece, with no immediate upgrade needed.
- It matches the current LTS that employers are likely to expect.
- Some tutorials and Stack Overflow answers target older versions, so code examples may need adapting.
- Newer SDKs can still build older target frameworks, so installing .NET 10 does not break other .NET 8 projects on the machine.
- If a dependency lacks .NET 10 support, record the exception in a new ADR rather than silently downgrading.
- The next LTS release will mean a planned upgrade. Revisit this ADR then.
